## 一、概述

### 1.1 定位

AnnoHub 是一套部署在普通 Windows 电脑上的图像标注平台。服务端与浏览器界面合并在一个可执行文件里，启动后同网段的成员用浏览器访问即可协同标注，不需要安装客户端，也不需要连外网。

平台把大图切块、图片归集、多人标注、模型预标注与格式导出串成一条链路，面向需要自建数据集的研究组与小团队。

### 1.2 具备的能力

| 环节 | 能力 |
|---|---|
| 图片准备 | 任意尺寸大图按指定窗口切块，支持重叠与贴边对齐；已裁好的图片可整目录导入 |
| 标注形式 | 矩形框、多边形、折线、点、画笔、整图分类，可在同一张图内混用 |
| 协作 | 任务分配、图片级独占锁、进度统计、按成员与按分组查看完成度 |
| 预标注 | 导入 ONNX 模型（检测、分割、分类），支持单张、勾选若干张、整批三种跑法 |
| 导出 | YOLO 检测、YOLO 分割、YOLO 分类、Pascal VOC、COCO、CSV 六种格式，十种划分比例 |
| 数据交换 | 可读入 YOLO txt、VOC xml、COCO json、LabelMe json、CSV 五种既有标注 |

### 1.3 不适用的场景

以下情形改用专门工具更省事：

- 视频逐帧标注。平台以静态图片为单位，不解析视频容器。
- 三维点云与多层医学影像序列（DICOM）。没有对应的数据模型。
- 跨公网、跨地域协作。平台按局域网设计，未做 TLS 与账号体系加固，直接暴露到公网存在风险。
- 浏览器内训练。平台只负责标注与导出，不含训练功能。

### 1.4 术语约定

| 术语 | 含义 |
|---|---|
| 项目 | 一次标注任务的容器，拥有独立的类别字典、图片目录与导出记录 |
| 分组 | 项目下图片的来源单位。一次裁切产生一组，一次导入产生一组 |
| 标注 | 一条几何记录，包含类别、几何类型、坐标与来源（人工或模型） |
| 几何类型 | rect 矩形、polygon 多边形、line 折线、point 点、classify 整图标签 |
| 锁定 | 某张图被某个成员占用期间，其他人只能查看不能编辑 |
| 预标注 | 用 ONNX 模型先跑一遍，生成待人工修正的标注初稿 |
| 划分 | 导出时把图片分配到 train / val / test 的比例 |

## 二、运行环境与安装

### 2.1 硬件与系统要求

| 项目 | 最低 | 建议 |
|---|---|---|
| 操作系统 | Windows 10 64 位 | Windows 11 64 位 |
| 内存 | 4 GB | 8 GB 以上 |
| 磁盘 | 2 GB 可用 | 按图片量估算，1 万张 640×640 图片约 1.5 GB |
| 网络 | 与协作成员处于同一局域网 | 有线连接，避免无线丢包 |

服务端不需要独立显卡。预标注可另装 GPU 版 onnxruntime 提速，不装也能运行，只是推理较慢。

### 2.2 安装（单文件版）

1. 新建一个目录，例如 `F:\_AnnoHub`。
2. 把 `AnnoHub.exe` 放入该目录。
3. 双击运行。首次启动会在同目录生成 `data` 文件夹，用于存放数据库、图片与导出包。
4. 浏览器自动打开 `http://127.0.0.1:8765`，用内置管理员账号登录。

`AnnoHub.exe` 与 `data` 应始终位于同一目录，分开存放会让迁移时漏掉数据。

程序是绿色版，不写注册表、不装系统服务、不建开机自启项。删除整个目录即完成卸载，但 `data` 中的数据会一并删除，卸载前请先备份。

### 2.3 从源码运行

适合需要改动代码或调试的场景，要求 Python 3.10 以上。

```bash
cd 02_源码/annohub
pip install -r requirements.txt
python run.py
```

源码运行时数据目录默认位于 `02_源码/annohub/data`，可用环境变量 `ANNOTOHUB_DATA` 指向其他位置。

### 2.4 启动参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--port 8765` | 8765 | 监听端口。被占用时自动向后寻找至多 30 个端口，并在窗口中打印实际端口 |
| `--host 0.0.0.0` | 0.0.0.0 | 监听地址。改为 `127.0.0.1` 则只允许本机访问 |
| `--no-browser` | 关闭 | 启动后不自动打开浏览器，适合放入任务计划 |
| `--reset-admin [密码]` | 无 | 重置管理员密码后退出，缺省重置为 `admin123` |
| `--promote 用户名` | 无 | 把已有账号提升为管理员后退出 |
| `--list-users` | 无 | 打印全部账号后退出 |

后三个参数属于账号维护命令，执行完立即退出，不启动服务，详见 3.7。

### 2.5 停止与重启

关闭控制台窗口即停止服务。断网、休眠、注销都会导致成员端请求失败，标注页会提示无法连接到服务。

服务端不做热更新。替换 `AnnoHub.exe` 前必须先关闭旧进程，否则文件被占用无法覆盖。数据库使用 WAL 模式，正常关闭后 `annohub.db-wal` 会自动合并；强制结束进程可能残留该文件，下次启动自动恢复，不需要手工删除。

### 2.6 数据目录

单文件版的数据目录固定在可执行文件同级的 `data`：

```
data/
├─ annohub.db          主数据库（SQLite）
├─ projects/           每个项目一个子目录
│  └─ 1/
│     └─ images/       按分组再分子目录：1、2、3……
├─ thumbs/             缩略图缓存，可随时删除
├─ exports/            导出生成的 zip 包
├─ models/             模型库（ONNX）
└─ logs/               运行日志
```

`thumbs` 与 `logs` 属于可再生成的缓存，迁移时可以不带走。`annohub.db` 与 `projects` 必须成对迁移，缺一不可。

## 三、账号与权限

### 3.1 角色与权限

平台只有两种角色。

| 能力 | 管理员 | 标注员 |
|---|---|---|
| 新建、修改、归档、删除项目 | 有 | 无 |
| 修改类别、绑定预标注模型、导出权限设置 | 有 | 无 |
| 裁切与导入图片 | 有 | 有 |
| 标注、预标注、删除单张或整组图片 | 有 | 有 |
| 分配任务 | 可分配给任意成员 | 只能分配给自己 |
| 导出数据 | 有 | 默认仅导出自己完成的部分，见 9.5 |
| 成员管理、系统设置、注册开关 | 有 | 无 |
| 模型库 | 管理 | 查看与测试 |

标注员日常只需要项目、图片、标注三页，其余入口不出现在左侧导航中。

### 3.2 首次登录

内置管理员账号固定为 `admin`，初始密码 `admin123`。首次登录后建议立即修改密码。

修改入口有两处：左下角账号菜单的修改密码，或由管理员在成员页重置。

### 3.3 成员自助注册

默认开启。登录页有登录与注册两个页签，成员填写用户名、显示名、密码即可注册。约束如下：

| 字段 | 规则 |
|---|---|
| 用户名 | 3 至 24 个字符，全局唯一，建立后不可修改 |
| 显示名 | 可留空，留空时使用用户名 |
| 密码 | 至少 6 位 |

注册成功即自动登录，角色为标注员。

若组织内部要求账号统一由管理员发放，可在成员页关闭"允许自助注册"。关闭后注册入口消失，只保留登录。

### 3.4 注册审批

与自助注册配套的开关是"注册后需审批"。开启后新注册账号处于待审状态，无法登录；管理员在成员页顶部的"等待审批"卡片中逐一点通过或拒绝。

拒绝等同于删除该账号，用户名可被重新注册。审批开关仅在自助注册开启时有意义。

### 3.5 管理员创建账号

成员页右上角"新建账号"可直接建立，可指定角色与初始密码，适合给不熟悉注册流程的成员开号。

### 3.6 重置密码

管理员在成员表中点"重置密码"，输入新密码即可。标注员本人忘记密码时需联系管理员，平台不提供邮件或短信找回。

### 3.7 忘记管理员密码

在运行本程序的那台电脑上打开命令提示符，进入程序所在目录，执行：

```
AnnoHub.exe --reset-admin
```

管理员密码恢复为 `admin123`，账号同时被置为启用状态。也可以直接指定新密码：

```
AnnoHub.exe --reset-admin MyNewPass2026
```

其他相关命令：

```
AnnoHub.exe --list-users               查看全部账号
AnnoHub.exe --promote Oryza_G          把某个账号提升为管理员
```

`--promote` 适用于一直使用自注册账号、又需要管理权限的情形，执行后无需重建项目。这三条命令都不启动服务，执行完立即退出。

### 3.8 停用与删除账号

| 操作 | 结果 |
|---|---|
| 停用 | 账号保留但无法登录，已分配的图片仍记在其名下。成员暂时离开时使用 |
| 删除 | 账号与登录信息移除，其已完成的标注保留 |

删除账号前确认没有进行中的任务，否则这些图片需要重新分配。

## 四、项目管理

### 4.1 新建项目

进入项目页，点右上角"新建项目"，填写：

| 字段 | 说明 |
|---|---|
| 项目名称 | 建议写成"做什么 + 时间或地块"，例如"早稻秧苗计数 2026-06" |
| 项目类型 | 四选一，见 4.2 |
| 类别 | 英文逗号分隔，顺序即导出时的类别编号，从 0 开始 |
| 说明 | 可留空，用于记录拍摄条件、标注口径等约定 |

类别可以在建项目时先填，也可以稍后在设置页补充。类别集为空会导致标注页没有可选类别，务必至少填一个。

### 4.2 项目类型的含义与边界

| 类型 | 主要产出 | 界面差异 |
|---|---|---|
| 目标检测 | 矩形框为主 | 五种工具全开 |
| 实例分割 | 多边形为主 | 五种工具全开 |
| 图像分类 | 一张图一个类别 | 不显示画布工具，右侧为类别单选按钮组 |
| 其他 | 关键点、折线、旋转框等 | 五种工具全开 |

需要明确一点，类型只描述这个项目主要产出什么，不限制标注方法。除图像分类外，其余三种类型的画布都同时开放矩形、多边形、折线、点、画笔，标注过程中可随时切换。这样处理的原因是实际数据里常常混着不同形态的目标，事先锁死工具反而妨碍标注。

导出格式的默认选项会根据类型预选，仍可手动改为任意适用格式。

### 4.3 类别字典

类别是项目级字典，标注时只能从中选择，不能临时输入新名字，目的是避免多人协作时同一目标出现多个叫法。

修改类别名有两种方式：

| 方式 | 效果 |
|---|---|
| 直接改类别列表 | 只影响新建标注，已有标注仍保存旧名字，导出时旧名字会被追加成新编号 |
| 替换已有类别 | 把已标好的对象从旧类别整体改为新类别，用于清理同物异名 |

类别顺序决定导出编号。训练脚本里的类别表必须与导出包的 `data.yaml` 一致，改动顺序后应重新导出。

### 4.4 项目设置项

| 设置 | 作用 |
|---|---|
| 项目名称、说明 | 展示与检索 |
| 项目类型 | 影响新建标注时的默认工具与默认导出格式 |
| 类别列表 | 见 4.3 |
| 预标注模型 | 指定本项目默认使用的 ONNX 模型，留空则跟随全局默认 |
| 允许标注员导出全量 | 关闭后标注员只能导出自己完成的部分，见 9.5 |

### 4.5 存储位置

项目设置页列出两行路径：项目目录与图片目录。

- 项目目录：`data/projects/<项目号>`
- 图片目录：`data/projects/<项目号>/images`，其下按分组号分子目录

两个路径都可一键复制。在本机访问时旁边还有"打开"按钮，可直接在资源管理器中定位；从其他电脑通过局域网访问时不显示该按钮，因为打开的是服务端电脑的目录。

标注数据存在数据库中，不单独落文件。备份时复制整个 `data` 目录最稳妥。

### 4.6 归档与删除

两者性质完全不同，误用会造成数据丢失。

| 操作 | 结果 | 可恢复 |
|---|---|---|
| 归档 | 从进行中列表收起，图片、标注、导出记录全部保留 | 可随时取消归档 |
| 删除 | 数据库记录、图片文件、缩略图、导出包一并移除 | 不可恢复 |

项目结题、暂停标注、留作存档，用归档。只有建错了、数据确定不要时才用删除。删除前系统会再次确认，并显示该项目下的图片数量。

两处入口：

- 项目列表：鼠标移到卡片上，右下角出现"删除"；已归档项目的卡片底部直接显示"恢复"与"删除"。
- 项目设置页：底部"项目状态"区域，归档与删除分区展示。

归档与删除只有管理员可以执行。标注员看不到这些按钮，项目设置页会提示需要管理员权限。

项目列表右上角有筛选：进行中的项目、已归档的项目、全部项目。

## 五、准备图片

### 5.1 三条进入项目的路径

| 路径 | 适用情形 | 入口 |
|---|---|---|
| 裁切 | 手上有原始航拍或大尺寸照片 | 项目 → 裁切 |
| 导入图片 | 图片已切好，或来自其他渠道 | 项目 → 导入（左） |
| 导入标注 | 把别人标好的结果贴到已有图片上 | 项目 → 导入（右） |

三条路径都会在项目下建立分组，互不混淆。

### 5.2 大图裁切

裁切页只负责切图，不判断空图，也不做多光谱另存。参数如下：

| 参数 | 默认 | 说明 |
|---|---|---|
| 小图宽 / 高 | 640 × 640 | 训练常用尺寸，宽高可以不等 |
| 横向 / 纵向重叠 | 128 px | 相当于 20%。重叠越小张数越少，目标被切断的概率越高。密集小目标建议 15% 至 25% |
| 输出格式 | JPG | 可选 JPG 或 PNG。PNG 无损，体积约为 JPG 的 3 至 5 倍 |
| JPG 质量 | 95 | 仅在输出 JPG 时生效。低于 85 会明显掉细节 |
| 递归子目录 | 是 | 源目录含多层时是否全部读取 |
| 只读前 N 张 | 0 | 0 表示不限。试参数时填 1 至 2，几秒即可看到效果 |

边缘处理采用贴边对齐。剩余宽度不足一个完整窗口时，最后一个窗口向左平移至图像边缘，保证不留黑边、不丢内容。因此边缘处相邻窗口的实际重叠量可能大于设定值，这是预期行为。

预演只读取图片尺寸并抽样检查边缘窗口，不改动任何文件，可反复调整参数后再正式执行。预演结果会显示预计张数与边缘块标记。

### 5.3 导入已裁好的图片

在导入页左卡选择源文件夹或逐张挑选图片，填写组名后开始导入。

导入时的处理规则：

- TIF、BMP 等格式统一转换为 JPEG，保证后续读取一致。
- 内容完全相同的图片按 SHA-256 哈希判重，重复的跳过，不占用标注人力。
- 原文件名中的特殊字符替换为下划线，保留中文。
- 图片较多时后台执行，页面显示进度，可离开该页，回来后仍能看到结果。

### 5.4 命名规则

平台对图片统一重命名，规则为"组号-原名"：

| 来源 | 格式 | 示例 |
|---|---|---|
| 裁切 | `组号-源图名-r行c列.扩展名` | `04-DJI_0021-r001c000.jpg` |
| 导入 | `组号-原文件名.扩展名` | `05-IMG_2041.jpg` |

组号放在最前面的原因是按文件名排序时同一组自动连在一起，与左侧分组顺序一致。行号列号从 0 开始，三位补零，便于核对切块位置。

重名时追加序号，例如 `05-IMG_2041_2.jpg`，不会覆盖已有文件。

### 5.5 来源分组

分组是项目下图片的一级归类，由 `batches` 表承担，其 `kind` 字段区分裁切与导入。

图片页左侧列出全部分组，每组显示名称、类型标签与张数。点击切换筛选，鼠标移到分组上出现删除按钮，可整组移除。

分组名默认取源文件夹名，可在裁切或导入时自定义。建议按"日期 + 地块"命名，例如"0601 一号田"，便于后续按组导出。

### 5.6 图片页操作

顶部筛选条支持四项组合：标注状态、有无标注、文件名搜索、只看我负责的。

选中图片有两种方式：单击选单张，勾选左上角复选框可多选。选中后底部出现操作条：

| 操作 | 说明 |
|---|---|
| 预标注选中 | 只对选中的这几张跑模型 |
| 分配给我 | 把选中图片的负责人设为自己 |
| 取消分配 | 清空负责人 |
| 删除选中 | 移除图片文件与标注，不可恢复 |
| 取消选择 | 清空当前选择 |

图片卡片显示缩略图、文件名与标注条数。点击卡片进入标注页。

## 六、标注作业

### 6.1 界面构成

标注页分为四区：

| 区域 | 内容 |
|---|---|
| 顶栏 | 返回、当前文件名与序号、完成与跳过、预标注、标注说明 |
| 左侧列表 | 按来源分组的文件名清单，组标题显示"组名 已完成/总数"，可折叠，顶部可按文件名筛选 |
| 中央画布 | 图片与标注图形 |
| 右侧面板 | 类别选择、本图标注列表、图片信息 |

左侧不加载缩略图。图片量大时逐张请求缩略图既慢又占内存，标注时真正需要判断的是这一组还剩几张，文件名比小图更容易扫视。当前图的尺寸、来源与标注构成在右侧面板单独展示。

### 6.2 五种画布工具

| 工具 | 快捷键 | 操作方式 |
|---|---|---|
| 矩形框 | W | 按住拖拽拉出框 |
| 多边形 | P | 依次单击加顶点，回到起点或双击闭合 |
| 折线 | L | 依次单击加折点，双击结束 |
| 点 | K | 单击落一个关键点 |
| 画笔 | B | 按住拖动描出轮廓，松手自动闭合成多边形 |
| 选择 | V | 点选、拖动、拖顶点改形状 |

画笔与多边形的区别：画笔连续采样鼠标轨迹，适合贴合不规则轮廓；多边形逐点精确，适合边界清晰的规则目标。画笔生成的结果同样是多边形，导出顶点数与采样密度相关，不宜过密，否则标注文件体积偏大。

在选择工具下可拖动顶点调整形状。拖到与相邻点重合时会被过滤，不会产生退化图形。

### 6.3 几何模型

所有坐标统一使用原图像素坐标，左上角为原点，x 向右，y 向下。缩放在渲染层完成，数据库与导出文件中的坐标不缩放、不取整，保留 6 位小数。

| 几何类型 | 数据结构 |
|---|---|
| rect | `[x1, y1, x2, y2]` |
| polygon | `[[x, y], [x, y], ...]`，至少 3 点 |
| line | `[[x, y], [x, y], ...]`，至少 2 点 |
| point | `[x, y]` |
| classify | `[]` |

矩形同时冗余存储 x1、y1、x2、y2 四列，用于快速统计与筛选；这四列由几何数据反算，不需要单独维护。

### 6.4 快捷键

| 按键 | 功能 |
|---|---|
| W / P / L / K / B / V | 切换工具 |
| A / D | 上一张 / 下一张 |
| 1 至 9 | 切换当前类别 |
| Delete | 删除选中的标注；绘制多边形时删除上一个点 |
| Esc | 取消正在绘制的图形；取消选中 |
| Enter | 完成当前图并进入下一张 |
| Ctrl + S | 保存，不解除锁定，可继续修改 |
| Ctrl + Z / Ctrl + Shift + Z | 撤销 / 重做 |
| Ctrl + D | 复制选中的标注 |
| 方向键 | 微调 1 像素；按住 Shift 为 10 像素 |
| 滚轮 | 以光标位置为中心缩放 |
| 空格 + 拖动 | 平移画布 |
| 双击标注 | 编辑该标注的类别与坐标 |

### 6.5 状态流转

| 状态 | 含义 | 进入方式 |
|---|---|---|
| 待标 | 尚无人工标注 | 新建或撤回 |
| 进行中 | 有标注但未完成 | 保存后自动进入 |
| 已完成 | 标注完成 | 点"完成"或按 Enter |
| 已复核 | 已通过检查 | 复核人标记 |

导出范围中的"全部已标注"包含已完成与已复核两种状态，"复核通过"只含后者。

### 6.6 并发与锁定

同一张图在同一时刻只允许一人编辑。打开图片时客户端申请锁，服务端记录锁定人与时间。

| 项目 | 数值 |
|---|---|
| 心跳间隔 | 30 秒 |
| 锁超时 | 90 秒 |
| 冲突处理 | 保存时校验版本号，不匹配返回 409 |

成员关闭浏览器、断网或直接离开，90 秒后锁自动释放。其他成员打开被占用的图片时，画布可看不可改，左侧列表对应行标记为占用。保存时如果期间有人改过，服务端拒绝写入并提示刷新，避免覆盖他人工作。

不要在两个浏览器窗口里同时标注同一张图。第二个窗口会被拒绝，强行操作只会得到反复的冲突提示。

### 6.7 自动保存

编辑过程中每 30 秒自动保存一次草稿，切换图片时也会保存。自动保存不改变图片状态，仍是进行中。

存在未保存修改时返回项目页会先询问是否保存。异常退出最多丢失 30 秒内的操作。

### 6.8 分类标注

图像分类项目的标注页没有画布工具，右侧面板是一组类别按钮。单击即选定该图的类别，一张图只有一个类别，再次点击其他类别会替换。

同一张图不允许出现两个分类标签。若确实存在多标签需求，应改用"其他"类型并在项目说明中约定命名规则，或拆成多个项目。

### 6.9 标注口径建议

平台不强制标注规则，以下几条在多人协作中反复出问题，建议在建项目时写进项目说明：

1. 只标完整可见的目标。被图像边缘切断超过一半的不标。
2. 框要贴紧目标轮廓，不要留大边距，也不要切掉目标边缘。
3. 同一目标只标一次。密集处先标大的再标小的，避免漏标或重复。
4. 拿不准的目标跳过，不要猜。漏标比错标更容易在复核阶段发现。
5. 类别只从字典里选。字典不够用时联系管理员补充，不要私下改名。

标注页顶栏的"标注说明"按钮会显示当前项目可用的工具与快捷键，不必翻手册。

## 七、预标注

### 7.1 模型要求

模型库只接受 ONNX 格式。PyTorch 的 `.pt` 需先转换：

```bash
python tools/export_onnx.py --weights best.pt --imgsz 640
```

输入输出约定：

| 类型 | 输入 | 输出 |
|---|---|---|
| 检测 / 分割 | 1×3×640×640，RGB，归一化至 0 至 1 | 检测为 `[1, N, 6]`，即 x1, y1, x2, y2, conf, cls；分割另带掩膜或原型 |
| 分类 | 1×3×224×224 或模型自身尺寸 | `[1, C]` 各类别得分 |

模型自带的类别顺序需与项目类别一致，否则预标注结果的类别会错位。上传时可在模型描述中记录类别表。

### 7.2 模型库操作

模型库页支持上传、从本地路径导入、设为默认、测试、删除。

| 操作 | 说明 |
|---|---|
| 上传 | 选择 `.onnx` 文件，指定任务类型与名称 |
| 从本地路径导入 | 直接填写服务端磁盘路径，省去先上传到浏览器再转存的步骤，适合大模型 |
| 测试 | 选一张图跑一次，显示检出数量、类别与置信度 |
| 默认 | 全站默认模型，项目未单独指定时使用 |

模型文件存放在 `data/models`，删除模型不影响已生成的标注。

### 7.3 三种跑法

| 跑法 | 入口 | 适用 |
|---|---|---|
| 单张 | 标注页顶栏"预标注" | 边标边补，只处理当前图 |
| 勾选若干张 | 图片页选中后"预标注选中" | 只处理某一批难点样本 |
| 整批 | 图片页未选中时"批量预标注" | 首次铺量，按上限跑 |

整批跑会跳过已有模型标注的图片，避免重复叠加。批量任务的进度在页面顶部显示，可离开该页。

### 7.4 置信度与结果处理

预标注生成的标注带模型来源标记与置信度，在右侧列表中与人工标注区分显示。

建议流程为预标注、逐张修正、点完成。不要把模型结果直接当作成品导出，检测模型在密集小目标上漏检明显，分割模型在遮挡处边界不稳。

置信度阈值在服务端配置，默认 0.25。小目标多时适当降低，误检多时提高。

### 7.5 分类模型

分类模型对每张图输出一个类别，直接写入该图的整图标签。分类项目不需要画布，预标注后人工只需确认或改判。

### 7.6 排查

| 现象 | 可能原因 |
|---|---|
| 预标注按钮无反应 | 项目未绑定模型，且模型库没有默认模型 |
| 提示模型输入尺寸不符 | 模型导出时固定了尺寸，与图片实际尺寸差异过大。平台会先缩放再推理，仍失败则重新导出为动态尺寸 |
| 全部图片零检出 | 类别表不匹配，或模型未针对该类目标训练。先用测试功能验证 |
| 推理很慢 | 使用 CPU 版 onnxruntime。可换 GPU 版，或在模型库降低输入尺寸 |

## 八、数据导出

### 8.1 导出范围

| 范围 | 包含 |
|---|---|
| 全部已标注 | 状态为已完成或已复核的图片 |
| 我标注的 | 分配给我且已完成的图片 |
| 复核通过 | 只含已复核的图片 |
| 指定来源分组 | 某一组裁切或导入的图片 |
| 全部图片（含未标注） | 含未标图片，用于先看数据分布或做纯推理集 |
| 仅图片，不含标签 | 只打包图片，不含任何标注文件 |

标注员默认只能选择与自己相关的范围，管理员可在项目设置中放开，见 9.5。

### 8.2 划分比例

平台提供十种预设：

| 预设 | train : val : test |
|---|---|
| 不划分 | 全部放 train |
| 9 : 1 | 9 : 1 : 0 |
| 8 : 2 | 8 : 2 : 0 |
| 7 : 3 | 7 : 3 : 0 |
| 3 : 1 | 3 : 1 : 0 |
| 1 : 1 | 1 : 1 : 0 |
| 8 : 1 : 1 | 8 : 1 : 1 |
| 7 : 2 : 1 | 7 : 2 : 1 |
| 6 : 2 : 2 | 6 : 2 : 2 |
| 7 : 1.5 : 1.5 | 7 : 1.5 : 1.5 |

划分采用固定随机种子，同一项目重复导出得到相同划分，便于对照实验。种子可在导出选项中指定，改动种子会重新分配。

划分以图片为单位，不是以目标为单位。目标密集且分布不均时，某一类可能在验证集中样本过少，这种情况需要在导出后人工调整，或自行分层抽样。

### 8.3 六种格式对照

| 格式 | 目录结构 | 适用 |
|---|---|---|
| YOLO 检测 | `images/` `labels/` `data.yaml` | 目标检测训练 |
| YOLO 分割 | `images/` `labels/`，每行含多边形顶点 | 实例分割训练 |
| YOLO 分类 | `images/{train,val}/{类别}/` | ImageFolder 结构，直接用于分类训练 |
| Pascal VOC | `JPEGImages/` `Annotations/` `ImageSets/` | 通用交换格式，工具兼容性好 |
| COCO | `instances_{split}.json` | 含 segmentation 与 keypoints，适合分割与关键点 |
| CSV | 单表 | 统计核对、自行转换 |

各格式的转换约定：

- YOLO 检测：多边形与折线取外接矩形，点转为 4 像素见方的小框，避免退化成无效行。
- YOLO 分割：矩形自动展开为四个顶点，折线不写入，点同样处理为小方框。
- VOC：多边形写入 polygon 节点，点写入 point，折线写入 polyline。
- COCO：折线跳过，其余几何分别映射到 bbox、segmentation、keypoints。
- CSV：一行一个标注，保留几何类型与原始坐标。

### 8.4 YOLO 检测与分割共存

同时勾选 YOLO 检测与 YOLO 分割时，两者不能写入同一目录，否则以最后一次写入为准，先前文件被覆盖。

平台的解决方式是分目录输出：

```
images/
labels/          YOLO 检测（矩形）
labels_seg/      YOLO 分割（多边形）
data.yaml
README_yolo.txt  说明哪个目录对应哪种训练
```

只勾选其中一种时，目录恢复为常规的 `labels/`。训练时按 `README_yolo.txt` 的说明指定标签目录。

### 8.5 分类目录结构

YOLO 分类导出后可直接被 Ultralytics 或 `torchvision.datasets.ImageFolder` 读取：

```
images/
├─ train/
│  ├─ healthy/
│  └─ blight/
└─ val/
   ├─ healthy/
   └─ blight/
```

没有标注文件。类别目录名取自项目类别字典，划分结果决定图片落在 train 还是 val。

### 8.6 CSV 字段

| 字段 | 含义 |
|---|---|
| image_id | 图片编号 |
| file | 导出包内的相对路径 |
| width / height | 原图尺寸 |
| split | 所属划分 |
| batch_id | 来源分组号 |
| cls_id / cls_name | 类别编号与名称 |
| geom_type | 几何类型 |
| geom | 原始几何坐标，JSON 串 |
| conf | 置信度，人工标注为空 |
| source | human 或 model |

### 8.7 包内清单

每个导出包附带两个文件：

- `manifest.csv`：逐图记录编号、文件名、划分、来源分组、源图名与偏移、状态、标注条数，用于回溯某张图来自哪张大图的哪个位置。
- `README.txt`：记录项目名、导出范围、格式、图片数、标注条数、类别表。

### 8.8 导出后校验

训练前建议做三项检查：

1. 图片数与标注文件数是否匹配。检测与分割任务允许存在无标注负样本，但数量应可控。
2. `data.yaml` 的类别顺序是否与训练脚本一致。
3. 随机抽三张叠加可视化一次，确认坐标没有整体偏移。

导出记录保留在项目内，可下载历史包。删除项目会连带删除这些包，见 4.6。

## 九、多人协作

### 9.1 分工方式

| 方式 | 适用 | 操作 |
|---|---|---|
| 按人分片 | 数据量大、成员能力平均 | 每人固定一组或固定若干张 |
| 抢占式 | 人少、数据零散 | 不预先分配，谁空谁标未锁定的图 |

按人分片便于统计进度，也便于复核时定位责任人。抢占式启动快，但进度统计意义不大。

### 9.2 派活流程

管理员在项目概览页的"按成员"卡片右上角点"分配任务"，或点击表格中某一行右侧的"分配"。

弹窗中指定成员、来源分组、张数，以及两个可选条件：只挑还没分配给别人的图、已完成的一起分（用于返工）。

确认后系统按分组顺序取未被分配的图片，写入负责人字段。管理员可以把图派给任意成员，标注员只能派给自己。

也可以在图片页多选后点"分配给我"，适合临时补几张。

### 9.3 进度查看

项目概览页提供三个视角：

| 视角 | 内容 |
|---|---|
| 总体 | 总张数、待标、进行中、已完成、已复核 |
| 按成员 | 每人已领张数与完成数 |
| 按分组 | 每组张数与完成数 |

图片页左侧分组标题同样显示已完成与总数，逐组核对更方便。

### 9.4 冲突处理

平台用图片级锁避免同时编辑，仍有两种情况需要人工介入：

- 锁未释放：某人直接关掉浏览器，90 秒内图片显示占用。等待即可，不需要干预。
- 版本冲突：保存时提示 409，说明期间有人改过这张图。刷新页面查看最新内容后重新标注，不要强制覆盖。

超过 10 分钟仍显示占用，通常是对方网络异常。可让该成员重新打开该图触发锁续期，或等待超时。

### 9.5 导出权限

项目设置中的"允许标注员导出全量"默认关闭。关闭时标注员只能导出自己完成的部分。

这样设计是为了避免多人各自下载一份全量数据，训练时反复覆盖同一份文件。需要全量数据时由管理员统一导出并分发。

## 十、局域网部署与排障

### 10.1 访问地址

启动窗口会打印三个地址：

| 形式 | 示例 | 特点 |
|---|---|---|
| 计算机名 | `http://Oryza-G:8765` | 推荐，IP 变化后仍然有效 |
| IPv4 | `http://192.168.1.20:8765` | 直接，但换网络后会变 |
| 本机回环 | `http://127.0.0.1:8765` | 仅服务端本机可用 |

设置页的"局域网访问"提供计算机名与各网卡 IP 的复制框，并附一段可直接转发给成员的说明文本。虚拟网卡、VPN 地址与 169.254 开头的未联网地址已从列表中过滤。

### 10.2 防火墙

成员打不开页面，多数情况是服务端防火墙未放行端口。判断方法：

- 服务端本机能打开 `http://127.0.0.1:8765`，成员不能，说明是防火墙或网络隔离。
- 服务端本机也打不开，说明服务没起来，看控制台是否报错。

处理方式有两种：

1. 以管理员身份重新运行程序，启动时自动添加放行规则。
2. 打开"设置 → 局域网访问"，点"一键放行端口"，在系统弹窗中确认。

放行规则针对 TCP 端口，对所有网络配置文件生效。系统把当前网络识别为公用网络时，Windows 默认拦截入站连接，必须显式放行。

### 10.3 连接自检

设置页"局域网访问"顶部的自检给出三项结论：

| 检查项 | 含义 |
|---|---|
| 端口监听 | 服务是否在预期端口上监听 |
| 防火墙规则 | 是否已存在放行规则 |
| 网卡地址 | 有哪些可用于访问的 IPv4 地址 |

任一项不通过，页面会直接给出处理建议，不必猜。

### 10.4 故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 成员浏览器提示无法访问此网站 | 防火墙未放行，或不在同一网段 | 见 10.2，并确认双方连的是同一路由 |
| 能打开页面但登录后空白 | 浏览器缓存了旧版脚本 | 强制刷新，Ctrl + F5 |
| 地址是 169.254 开头且打不开 | 本机未获取到有效 IP | 检查网线或无线连接 |
| 有人能连有人不能 | 交换机开启客户端隔离，或分属不同 VLAN | 联系网络管理员 |
| 换网络后地址失效 | IP 变化 | 改用计算机名访问 |
| 手机能连、电脑不能 | 电脑装了代理或 VPN，流量被劫持 | 关闭代理，或把局域网地址加入排除列表 |

## 十一、数据管理与备份

### 11.1 目录结构

```
_AnnoHub/
├─ AnnoHub.exe
├─ 使用手册.md
└─ data/
   ├─ annohub.db
   ├─ projects/
   │  └─ <项目号>/images/<分组号>/*.jpg
   ├─ thumbs/
   ├─ exports/
   ├─ models/
   └─ logs/
```

### 11.2 备份

必须备份的是 `annohub.db` 与 `projects`，两者要一起复制，只复制其中一个会得到不完整的项目。

推荐停掉服务后整体复制 `data`。不便停机时，用 SQLite 的在线备份命令生成一致性快照：

```bash
sqlite3 data/annohub.db ".backup backup/annohub-20261121.db"
```

直接复制正在写入的数据库文件可能得到损坏副本，务必使用上述方式或先停服务。

标注阶段建议每天备份一次，结题归档一次即可。

### 11.3 迁移到另一台电脑

1. 在新电脑准备相同版本的 `AnnoHub.exe`。
2. 关闭两边的服务。
3. 复制整个 `_AnnoHub` 目录，保持 `exe` 与 `data` 的相对位置不变。
4. 启动，用原有账号登录，项目与标注完整可见。

图片路径在数据库中记录为相对路径，迁移后不需要改配置。若只迁移 `data` 而不带 `exe`，把 `data` 放到新 `exe` 同级即可。

### 11.4 清理

| 目录 | 可否删除 | 影响 |
|---|---|---|
| `thumbs` | 可以 | 首屏缩略图重新生成，稍慢 |
| `logs` | 可以 | 丢失历史运行日志 |
| `exports` | 可以 | 已导出的 zip 包丢失，需要重新导出 |
| `models` | 谨慎 | 模型库中的文件消失，已生成的标注不受影响 |
| `projects` | 禁止 | 图片文件丢失，标注记录指向空文件 |

缩略图缓存体积随图片量增长，长期使用后可整体删除一次。

## 十二、性能与容量

### 12.1 建议规模

| 指标 | 建议上限 | 说明 |
|---|---|---|
| 单项目图片数 | 2 万张 | 超过后图片页翻页与筛选变慢 |
| 并发标注人数 | 8 人 | SQLite 写锁串行，更多并发会出现等待 |
| 单张图片尺寸 | 8000 × 8000 以内 | 浏览器解码大图占用内存 |
| 导出包大小 | 20 GB 以内 | 超过后浏览器下载容易中断，建议分批导出 |

### 12.2 常见瓶颈

- 磁盘读写：裁切与导入是磁盘密集型任务，机械硬盘上批量处理明显偏慢。
- 浏览器内存：同时打开多张超大图会累积解码缓存，标完一批建议刷新一次。
- 数据库写锁：多人同时保存会排队，表现为保存按钮短暂无响应，属正常现象。

### 12.3 参数建议

| 场景 | 建议参数 |
|---|---|
| 无人机航拍秧苗，目标密集 | 窗口 640，重叠 160 至 192 |
| 地面近景，目标较大 | 窗口 1024，重叠 64 至 128 |
| 只做分类，不检测 | 不需要裁切，直接导入整图 |
| 存储紧张 | 输出 JPG，质量 92 |

## 十三、命令行参数

| 参数 | 作用 |
|---|---|
| `--port N` | 指定端口，默认 8765 |
| `--host A` | 监听地址，默认 0.0.0.0 |

## 十四、常见问题

**登录后提示未登录或登录已过期**

会话过期或服务重启过。刷新页面重新登录。服务重启会使所有会话失效，属于预期行为。

**双击 exe 后窗口一闪而过**

多由安全软件拦截，或程序所在目录没有写入权限引起。把程序放到用户目录或非系统盘再试。

**启动后浏览器打开的是空白页**

端口被占用后可能自动切换了。看控制台打印的实际端口，手工访问该地址。

**成员注册后无法登录**

管理员开启了注册后需审批。在成员页顶部批准该账号。

**图片导入后数量比实际少**

内容完全相同的图片被判重跳过。这是设计行为，避免同一张图被多人重复标注。确实需要保留重复项时，先复制并改名再导入。

**裁切张数与预期不符**

边缘采用贴边对齐，最后一个窗口会向左平移，实际张数可能少于按窗口尺寸整除的结果。用预演核对后再执行。

**标注框整体偏移**

平台内部统一使用原图像素坐标，正常不会偏移。出现偏移通常是导出后用其他工具改过图片尺寸，检查源图片是否被替换。

**导出的 YOLO 数据集无法加载**

先看 `data.yaml` 的路径与类别数是否与训练脚本一致。同时勾选检测与分割时，标签目录是 `labels` 与 `labels_seg`，训练时要分别指定。

**预标注结果类别全错**

模型自带类别顺序与项目类别不一致。调整模型或项目的类别顺序后重新跑。

**图片显示占用但没人标**

对方异常退出，锁会在 90 秒后自动释放。等待后重新打开。

**保存时提示冲突 409**

期间有人改过同一张图。刷新页面查看最新内容再标，不要强行覆盖。

**能打开但不能删除项目**

删除只有管理员可以执行。用管理员账号登录，或执行 `AnnoHub.exe --promote 用户名` 提升权限。

**换了电脑后项目里图片显示为占位图**

只复制了数据库没有复制 `projects` 目录。补齐图片目录即可。
